# bug-bench · 专门解决 bug 的角色能力评测集

> 目的：客观测量「专门解决 bug 的角色」（带「评审-修复闭环护栏」壳）的
> 修复能力，并与基线（DeepSeek v4 flash / 外部 CodeBuddy）对比，
> 验证「壳」是否真的生效。

## 快速开始

```bash
# 运行全部评测用例（信号灯）
node bug-bench/run.js

# 运行单个用例
node bug-bench/run.js --case case-01

# 输出对比报告（统一判分器）
node bug-bench/compare.js --report

# 登记某执行者评测结果
node bug-bench/compare.js --record '<json>'
```

## 如何用于验证「壳」是否生效

1. **基线测量**：把 `bug-bench/baseline/` 下的原始 bug 版本交给基线（DeepSeek v4 flash / 外部 CodeBuddy）修复，
   用同一信号灯记录修复通过率与轮次。
2. **被测测量**：把同一批原始 bug 交给「专门解决 bug 的角色」（带壳）修复，
   用同一信号灯记录修复通过率与轮次。
3. **对比判定**（`bug-bench/compare.js --report`）：带壳角色通过率显著高于基线、轮次更少 → 壳生效；
   持平或更低 → 壳未产生增益。
4. **壳机制核对**：逐项检查带壳角色是否遵守「默认直接改 / 10 轮护栏 / 钩子没 bug 就停」。

## 当前评测结论（简要）

| 执行者 | 修复通过率 | 平均轮次 | 回归 |
|--------|-----------|---------|------|
| **带壳 bug 角色** | **100% (22/22)** | **1** | **0** |
| 无壳基线（侥幸直改） | 77% (17/22) | 2.3 | 3 |

> **✅ 壳生效**：高区分度场景下带壳通过率 +23pt、平均轮次 2.3→1、回归 3→0。
