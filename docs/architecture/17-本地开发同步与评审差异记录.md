# 17 · 本地开发同步与评审差异记录

> 记录 PR #26（NetMesh 真实 TCP 回环 mesh）评审中发现的问题、
> 本地开发与云端协作的同步差异，以及已确认没问题的可整合内容。

## 1. 背景

PR #26 在 `auto/netmesh-real-b3f1` 源分支上提交了 NetMesh 多节点 mesh 功能（`6e8fa97`），
经 CNB 评审 NPC 审核后给出 **「需修改」** 结论。

随后带壳 bug NPC 在评论中声称已修复评审阻断项并在本地提交 `78d9eda`，但 **CodeBuddy 核查确认
该提交在源分支及全仓库均不存在**——源分支 head 仍为 `6e8fa97`，mesh.test.js 仍为 8 项旧测试。

**疑因**：开发者在本地 Windows 环境完成修改后，未通过 `scripts/cnb-sync.js` / git push
同步到云端 PR 源分支，导致本地与云端的代码出现差异。

## 4. 修复完成记录

CodeBuddy 已在 PR 源分支 `auto/netmesh-real-b3f1` 完成以下修复：

### 已修复（评审阻断项）
1. **removeNode 幽灵 peer 残留** ✅
   - `NetTransport` 新增 `disconnect(peerId)` 方法
   - `NetMesh.removeNode` 遍历所有存活节点调用 `disconnect(被删节点)`，清除 socket/peer/channel
2. **addNode 建连失败回滚** ✅
   - 失败不再静默吞掉，收集失败 peers 后回滚新节点并抛错
   - 移除循环内冗余 registry 写入
3. **_settle 确定性就绪信号** ✅
   - 以"各节点 peer 数 == size-1"作为就绪条件，替代固定 sleep(120ms)
   - 50 次×10ms 轮询 + 超时兜底
4. **close() 外部 registry 防误清** ✅
   - 仅删除本 mesh 登记的条目，不清空注入的外部对象
5. **文档测试数校正** ✅
   - README/06/16 文档更新：core 48→51、总数 152→155

### 新增回归测试（mesh.test.js 8→11 项）
| 新增测试 | 验证内容 |
|---------|---------|
| removeNode 后拓扑校验 | 移除节点后其余节点 peers 不再残留被删节点 |
| addNode 失败回滚 | 建连失败后新节点不残留、mesh 状态回滚、原节点仍可通信 |
| close 外部 registry | 注入的外部共享 registry 中无关条目不被误清 |

### 验证结果
- `packages/core`：**51/51 全绿**（原 48 + 新增 3）
- net-policy 9 / relay-mesh 14 / compute 40 / content 29 / app 12 全绿
- **6 包 155 项测试全绿**
- bug-bench **57/57 (100%)** 全绿
