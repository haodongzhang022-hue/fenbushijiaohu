# 17 · 本地开发同步与评审差异记录

> 记录 PR #26（NetMesh 真实 TCP 回环 mesh）评审中发现的问题、
> 本地开发与云端协作的同步差异，以及已确认没问题的可整合内容。
> 用于团队对齐并推动修复闭环。

---

## 1. 背景

PR #26 在 `auto/netmesh-real-b3f1` 源分支上提交了 NetMesh 多节点 mesh 功能（`6e8fa97`），
经 CNB 评审 NPC 审核后给出 **「需修改」** 结论。

随后带壳 bug NPC 在评论中声称已修复评审阻断项并在本地提交 `78d9eda`，但 **CodeBuddy 核查确认
该提交在源分支及全仓库均不存在**——源分支 head 仍为 `6e8fa97`，mesh.test.js 仍为 8 项旧测试。

**疑因**：开发者在本地 Windows 环境完成修改后，未通过 `scripts/cnb-sync.js` / git push
同步到云端 PR 源分支，导致本地与云端的代码出现差异。

## 4. 待办修复清单

修复需在 PR #26 源分支 `auto/netmesh-real-b3f1` 上落地并推送：

### P0（评审阻断项）
1. **removeNode 幽灵 peer 残留**：移除节点时向每个存活节点的 transport 下发 disconnect，清理被删节点的 socket/peer/channel 登记
2. **addNode 建连失败回滚**：失败不再静默，回滚新节点并抛错；移除循环内冗余 registry 写入
3. **_settle 确定性就绪信号**：以各节点 peer 数 == size-1 作为就绪条件，替代固定 sleep(120ms)

### P1（质量改进）
4. **close() 外部 registry 防误清**：仅删本 mesh 登记的条目，不整体清空注入的外部对象
5. **文档测试数校正**：README/06 文档 core 测试数修正为实际值

### P2（测试固化）
6. mesh.test.js 扩展至 11 项：removeNode 后拓扑校验 / addNode 失败回滚 / close 外部 registry 防误清

## 5. 流程改进建议

| 建议 | 目的 |
|------|------|
