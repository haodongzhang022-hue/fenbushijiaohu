## 1. 关键假设清单与判定

| # | 关键假设 | 判定 | 依据 | 最小代价验证方式 |
|---|---------|------|------|----------------|
| F1 | 两用户可建立 P2P 消息直连 | ✅ 可行 | WebRTC DataChannel 成熟 | 两个浏览器页互发消息条 demo |
| F2 | NAT 后仍可连（多数网络） | ⚠️ 有风险 | 部分对称 NAT 需 TURN | STUN 连通率实测 + TURN 兜底 |
| F3 | 多端消息可收敛一致 | ✅ 可行 | CRDT（Yjs/Automerge）成熟 | 双端离线合并 demo |
| F4 | 贡献节点可跑分布式计算并聚合 | ✅ 可行 | 任务切分 + 结果校验经典模式 | 小规模 Map 归约 demo |
| F5 | 计算节点可能作恶 | ⚠️ 有风险 | 恶意返回错误结果 | 多副本 + 交叉校验 + 信誉分 |
| F6 | 视频可分布式传播 | ✅ 可行 | 内容寻址 + 分片分发（IPFS 模式） | 分片下载 demo |
| F7 | 跨平台/跨游戏统一大厅 | ⚠️ 有风险 | 依赖统一协议 + 各游戏接入适配 | 先定"会话协议 v1"，后接适配器 |
| F8 | 离线/局域网也可内部通讯 | ✅ 可行 | 本地优先 + mDNS 局域网发现 | 局域网直连 demo |
| F9 | 用户可自主选择联网策略 | ✅ 可行 | policy 层本地决策 | 策略开关配置 demo |

## 2. 风险等级汇总

| 等级 | 项 | 规避方案 | 状态 |
|------|----|---------|------|
| HIGH | F2 NAT 穿透 | 分层降级：P2P→中继，显式提示 | 有风险 |
| HIGH | F5 恶意计算 | 多副本校验 + 信誉阈值 | 有风险 |
| MEDIUM | F7 跨平台协议漂移 | 冻结 v1 契约 + 版本协商 | 有风险 |
| MEDIUM | 视频缓存存储膨胀 | 指纹去重 + LRU 淘汰 | 有风险 |
| LOW | 密钥丢失 | 本地备份 + 恢复码 | 可规避 |

---

## 3. 结论与排序
- **可先行落地（低风险高价值）**：F1 / F3 / F8 → 先做"分布式消息条"MVP。
- **需攻坚（高风险）**：F2 穿透、F5 校验 → 需专项设计与实测。
- **暂缓（依赖生态）**：F7 跨游戏大厅 → 依赖前端基础设施，放入 P2 里程碑。

> ✅ 可行性结论：**整体可行**，建议以「消息条 P2P 直连（F1/F3/F8）」为第一期最小可验证产物（MVP），先跑通闭环。
