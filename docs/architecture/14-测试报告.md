## 3. 缺陷分级清单

### 🔴 P0（阻塞）— 无
### 🟠 P1（严重）— 无
### 🟡 P2（一般，不阻塞合并）

| 编号 | 模块 | 缺陷 | 复现路径 | 影响 |
|------|------|------|---------|------|
| **P2-01** | policy | 构造函数不校验非法模式，与 `setMode` 行为不一致 | `new Policy('hacker-mode')` 不抛错，而 `setMode('hacker-mode')` 抛错 | 非法模式被静默接受，产生不可预期策略；接口契约不一致 |
| **P2-02** | identity | `sign()` 对非字符串输入抛未处理 `TypeError`，非优雅失败 | `id.sign(123)` / `id.sign(null)` | 非法入参未做类型防护，错误信息不友好 |
| **P2-03** | session | `merge()` 不校验 sender 签名，伪造身份消息被接收 | `session.merge({sender: alicePub, ...})` 无需 alice 签名即返回 true | 消息级防伪缺口；identity 提供 verify 但 session 未调用 |
| **P2-04** | transport | 明文透传，无认证/加密；未 connect 也可直接 send | `send` 明文 payload 可见；未 connect 即 send 对端仍收到 | 安全缺口（依赖上层/真实适配器补齐） |
| **P2-05** | session | `merge()` 缺字段（无 id/ts）消息被静默接受 | `merge({channelId:'c', type:'text', payload:'x'})` 返回 true | 畸形消息未做字段完整性校验，可能污染收敛视图 |
