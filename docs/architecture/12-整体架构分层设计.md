## 1. 四级粒度方法论（整体 → 粗纲 → 模块纲 → 细纲）

> 借鉴 dongjiagoushi 架构八步"由粗到细、AI 可读、人类可俯瞰"的核心理念，将项目架构从"顶层愿景"逐级细化到"可编码接口"，每一级只解答一个层级的"做什么/边界/依赖"，下一级只关注上一级点名的对象。

| 粒度级 | 名称 | 回答的问题 | 对应现有文档 | 完善动作 |
|--------|------|-----------|-------------|---------|
| **L0 整体设计** | 系统总纲 | 这套系统是什么？要达成什么？边界在哪？ | 01/02 顶层 | 收敛为一份"系统定位 + 架构总则 + 能力全景" |
| **L1 粗纲** | 子系统划分 | 拆成哪几个可独立演进的子系统？各自边界/依赖？ | 02 六层 | 明确 6 大子系统的接口面与演进独立性 |
| **L2 功能模块纲** | 模块清单与职责 | 每个子系统下有哪些模块？每个模块输入/输出/依赖/风险？ | 02 模块清单 + 04 契约 | 统一为"输入/输出/依赖/风险"四元组，标注状态机 |

**分阶段原则**：每级独立可评审、可验收；L0–L2 为"框架完整度"阶段（本次完成），L3 为"编码前契约"阶段（M1 前细化）。

## 2. L0 · 整体设计（系统总纲）

### 2.1 系统定位（一句话）
> 一套**分布式用户直连协作体系**：让用户本地优先、自愿联网、跨平台跨游戏地直接通讯、聚合算力、传播内容，实现**话语权回归本地**。

### 2.2 架构总则（沿用 02）
1. **分层解耦**：下层稳定、上层可插拔。
2. **本地优先**：数据先落本地，再按策略同步。
3. **自愿联网**：节点自主决定上线/离线/局域网。
4. **开放联邦**：跨平台统一协议，拒绝私有锁定。
5. **风险显式**：任何模块/接口/方案都要显式标注风险（10 号缺口 G 类补强）。

### 2.3 能力全景（C1–C5，来自 01）
| 能力 | 一句话 | 归属子系统 |
|------|--------|-----------|
| C1 点对点/多点消息直连 | 用户间直接通讯，消息条建立链接 | 通信/会话 |
| C2 分布式计算聚合 | 个体贡献算力/带宽，任务聚合 | 计算 |
| C3 内容传播 | 视频等内容的分布式分发 | 数据 |
| C4 低延迟游戏连线 | 跨游戏稳定连线与大厅 | 应用 |
| C5 话语权回归/跨平台 | 本地优先、自愿联网、开放联邦 | 信任/身份 |

### 2.4 顶层拓扑（沿用 02 的 Mermaid 图，此处引用不重绘）
> 六层分层：**通信 / 会话身份 / 数据 / 计算 / 信任策略 / 应用**。

## 3. L1 · 粗纲（子系统划分）

> 将六层收敛为 **6 大子系统**，每个可独立演进、独立交付、独立验收，并标注对外接口面与依赖。

| 子系统 | 对应层 | 职责一句话 | 对外接口面 | 演进独立性 |
|--------|--------|-----------|-----------|-----------|
| **S1 传输子系统** | L1 通信 | 把字节可靠送到对端，含穿透/中继/容错 | `Transport.connect/listen` | 高（不感知业务） |
| **S2 会话身份子系统** | L2 会话身份 | 身份凭据 + 消息条收敛一致 | `Identity` / `Message` | 高 |
| **S3 数据子系统** | L3 数据 | 内容寻址分发 + 分层存储 | `content` / `storage` | 中 |
| **S4 计算子系统** | L4 计算 | 任务切分、聚合、校验 | `compute` / `aggregator` / `verify` | 中 |
| **S5 信任策略子系统** | L5 信任策略 | 联网策略 + 信誉分 + 治理 | `policy` / `reputation` / `governance` | 高 |
| **S6 应用子系统** | L6 应用 | 游戏大厅 + 联邦协议 | `lobby` / `fed` | 中 |

**子系统间依赖（粗粒度）**：
```
S6 应用 ──依赖──▶ S2 会话 / S1 传输
S5 信任 ──横切──▶ 全部（授权+信誉，不存业务数据）
S4 计算 ──依赖──▶ S1 传输 / S2 会话 / S5 信誉
S3 数据 ──依赖──▶ S1 传输 / S2 会话
S2 会话 ──依赖──▶ S1 传输
```

## 5. L3 · 细纲（接口 / 数据 / 状态机）—— 编码前契约

> 本阶段在 M1 编码前逐模块细化。当前给出**框架级占位与首批重点模块细纲**（transport / session / identity / policy 为 M1 MVP 范围，先行细化）。

### 5.1 通用数据模型（消息条 v1，沿用 04）
```ts
interface Message {
  id: string;            // UUID / 内容哈希
  sender: string;        // sender pubKey
  channelId: string;     // 频道
  type: 'text' | 'media' | 'game-cmd' | 'task';
  payload: string;
  ts: number;            // Lamport/逻辑时钟（CRDT 收敛）
}
```

### 5.2 M1 重点模块细纲
| 模块 | 接口签名 | 数据模型 | 状态机 |
|------|---------|---------|--------|
| `transport` | `connect(peer): Channel` / `listen(cb): void` | `PeerDesc(ICE/SDP)` | `idle→connecting→open→closed` |
| `session` | `send(msg): void` / `onMessage(cb): void` | `Message` + CRDT doc | `init→syncing→converged` |
| `identity` | `sign(msg): sig` / `verify(pub,sig): bool` | `{publicKey}` | `generated→active→revoked` |
| `policy` | `canBroadcast()/shouldUseRelay(): bool` | `{mode:'online'|'lan'|'offline'}` | `online⇄lan⇄offline` |

> 其余模块细纲（compute/content/lobby/reputation/governance）在对应里程碑（M3/M4/M5/M6）前置阶段补充，本文件作为"活文档"持续下钻。
