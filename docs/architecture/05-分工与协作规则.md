## 2. 协作/接力规则
1. **契约先行**：所有跨模块交互以 `protos/*` 契约为准，改动需先改契约。
2. **模块独立可测**：每个模块有独立单测，接口 mock 先行。
3. **状态强制标注**：任务统一带 `todo / in_progress / blocked / failed / done`。
4. **风险显式上报**：任何 `blocked / failed` 必须记录原因，不吞异常。
5. **CP 暂停确认**：跨里程碑放行需人在 CP 点确认（见 06 进度对齐）。

---

## 3. 传消息规则（异步协作）
- 架构师发布契约 → 各工程师认领 → 实现 → 提交 PR → 架构师评审接口是否符合契约。
- 任何接口变更走 `protos` 契约 + 版本号（v1/v2），不允许隐性破坏。

## 4. 事件驱动协作机制（触发式优先 · 禁轮询）

> 原则：协作推进**必须走事件触发（webhook/钩子）**，静息状态下几乎零占用；
> **禁止用常驻 agent 轮询/监听**各 Issue/PR 进度来驱动协作，以免静息空转浪费资源。
> 类比硬件：平时低功耗待命，收到"高电平信号"（事件）才动作。

### 4.1 触发式信号灯（事件钩子 → 动作）

| 触发信号（事件钩子） | 唤醒谁 / 动作 | 静息占用 |
|--------------------|--------------|---------|
| `issue.open`（新建 Issue） | 分布式交互经理自动拆解派单 | 零 |
| `issue.comment@npc`（Issue 评论 @角色） | 被 @ 的角色 agent 触发式接力 | 零 |
| `pull_request`（提交 PR） | 测试信号灯 + 代码审查 + 带壳 bug 角色 | 零 |
| `pull_request.comment@npc`（PR 评论 @角色） | 被 @ 的角色 agent 评审交流/接力 | 零 |
| `pull_request.changes_requested`（评审打回） | 带壳 bug 角色自动修复重推 | 零 |
| `pull_request.mergeable`（可合并） | 评审门禁 + 自动合并 | 零 |

### 4.2 铁律
1. **触发式优先**：只有发生上述事件才唤醒对应 agent，**无事件 = 完全静默、零资源**。
2. **禁轮询/禁常驻监听**：任何 agent 不得以"持续盯着各 Issue 进度"的方式轮询常驻；
   各岗位的认领、评审交流、进度同步**一律靠事件（评论 @ / 提交 / 新建）触发**。
3. **事件链接力**：一事件产出物触发下一事件（如子 Issue 创建 → 各岗位 @认领 → 提 PR
   → 评审 → 合并），链路全由事件衔接，无需人工催办/轮询跟单。
4. **降级策略**：若某环节事件钩子未触发/失效，优先在对应 Issue/PR 评论中显式 @对应
   角色重新触发（等效手动"按一下高电平"）；仍不生效再评估补充机制，不默认回到轮询。
5. **进度同步**：经理/各角色的进度汇报只在"被事件唤醒"时输出，不主动周期性刷屏。

### 4.3 协作闭环（全事件驱动）
```
新建 Issue(issue.open) → 经理拆包 → 子 Issue(issue.open) → 各岗位 @认领(issue.comment@npc)
  → 提 PR(pull_request) → 评审/打回(pull_request.changes_requested / pull_request.comment@npc)
  → 修复重推(pull_request) → 可合并(pull_request.mergeable) → 合并 → 进度看板转绿
```
> 全链路由事件衔接，静息零占用；任何一步阻塞就靠事件 + 评论 @ 显式唤醒，不做轮询。
