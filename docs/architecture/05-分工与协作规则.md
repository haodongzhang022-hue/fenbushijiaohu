## 2. 协作/接力规则
1. **契约先行**：所有跨模块交互以 `protos/*` 契约为准，改动需先改契约。
2. **模块独立可测**：每个模块有独立单测，接口 mock 先行。
3. **状态强制标注**：任务统一带 `todo / in_progress / blocked / failed / done`。
4. **风险显式上报**：任何 `blocked / failed` 必须记录原因，不吞异常。
5. **CP 暂停确认**：跨里程碑放行需人在 CP 点确认（见 06 进度对齐）。

---

## 3. 传消息规则（异步协作）
- 架构师发布契约 → 各工程师认领 → 实现 → 提交 PR → 架构师评审接口是否符合契约。
- 任何接口变更走 `protos` 契约 + 版本号（v1/v2），不允许隐性破坏。

## 4. 权限不足时的升级处理规则

> 目的：协作中各角色/agent 在执行任务时若遇到**权限不足**（如无法操作某仓库/Issue/PR/CI），不得卡死或中断，统一按本规则升级处理。

1. **触发方式**：一旦出现权限不足（403/无权限/无法操作目标等），统一**在对应 Issue/PR 评论显式 `@CodeBuddy`** 触发升级处理。
2. **通用权限兜底**：`@CodeBuddy` 一般具备足够权限，可代为完成受权限限制的操作（读写文件、提交 PR、评审、CI 等）。
3. **不卡死原则**：权限不足属 `blocked`，按 05 规则 4「风险显式上报」必须显式上报原因，并附 `@CodeBuddy` 升级，禁止静默跳过或半途而废。
4. **触发式优先**：`@CodeBuddy` 升级遵循「触发式优先、禁轮询」机制（见 05 §3/05 事件驱动协作机制），仅在有权限事件（评论 @ 触发）时才被唤醒，静息零占用。
5. **流程闭环**：`@CodeBuddy` 处理后，在对应 Issue/PR 反馈处理结果，恢复到原协作流程继续推进。

## 5. 事件驱动协作机制（触发式优先 · 禁轮询）

> 原则：底层为纯事件驱动（webhook/高电平触发），有事件才被唤醒，静息状态几乎零占用。**禁止用轮询 / 常驻监听 agent** 驱动协作，防止静息空转浪费资源。

### 触发式信号灯表

| 事件钩子 | 唤醒谁 | 动作 | 静息占用 |
|---------|--------|------|---------|
| `issue.open` | 分布式交互经理 | 拆解派单工作包 | 零 |
| `issue.comment@npc` | 被 @ 的角色 | 触发式接力认领 | 零 |
| `pull_request` | 信号灯 + 审查员 + 带壳 bug 角色 | 测试 + 评审 + 闭环修复 | 零 |
| `pull_request.comment@npc` | 被 @ 的角色 | 触发式响应 | 零 |
| `pull_request.mergeable` | 合并门禁把关人 | 评审门禁 + 自动合并 | 零 |
| `pull_request.changes_requested` | 带壳 bug 角色 | 自动修复重提 | 零 |

### 铁律
1. **触发式优先**：一切协作动作由事件钩子驱动唤醒。
2. **禁轮询禁常驻监听**：禁止用 crontab/常驻 agent 轮询空转；表述上不得出现"持续监听/持续跟进"式轮询心智。
3. **事件链接力**：每个动作必须源于一个明确的触发事件（评论 @、open、PR 等）。
4. **降级策略**：某事件钩子未触发/失效时，先在对应 Issue/PR 评论**显式 @对应角色重新触发**（等效手动"按一下高电平"）；仍不生效再评估补充机制，**不默认回到轮询**。
5. **进度同步**：有产出即通过评论同步到 Issue/PR，不靠监听拉取。

---

## 6. 权限升级 × 事件驱动（合并示例）

- 经理拆包 → 各岗位子 Issue（触发式）
- 某岗位 agent 执行时权限不足（blocked）→ 评论 `@CodeBuddy`（触发式升级）→ CodeBuddy 代为完成 → 反馈结果 → 继续协作。
- 提 PR → 信号灯 + 评审 + 带壳修复（触发式）→ 合并。
- 全程无轮询，静息零占用。
