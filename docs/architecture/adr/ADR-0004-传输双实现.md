# ADR-0004 · 传输层采用 WebRTC + libp2p 双实现

## 背景
P2P 传输需要同时覆盖浏览器端与 Node/服务端两种运行环境。浏览器原生支持 WebRTC DataChannel（DTLS 加密），Node 环境适合 libp2p（Noise 加密 + yamux 多路复用）。需要统一抽象层同时支持两者。

## 选项
1. **统一 Transport 抽象 + WebRTC/libp2p 双适配器**
2. 仅 WebRTC（浏览器场景优先）
3. 仅 libp2p（Node 服务端优先）

## 决策
**采用统一 Transport 抽象 + WebRTC/libp2p 双适配器**，可插拔切换。

## 理由
- 两种环境覆盖不同用户场景，需同时支持。
- 统一接口契约（connect/listen/send/onData/close）屏蔽底层差异，上层不感知。
- 内存模拟通道保留用于测试与 CI，降低依赖成本。

## 否决项
- 仅 WebRTC 无法覆盖 Node 守护进程场景，否决。
- 仅 libp2p 无法覆盖浏览器端用户，否决。

## 影响
- `packages/core/src/transport/` 下实现 `Transport` 基类 + WebRTC/libp2p/Memory 三个适配器。
- 上层（session/app/fed）通过统一接口使用传输能力。
- NAT 穿透风险由 relay-mesh（M2a）作为中继兜底。
