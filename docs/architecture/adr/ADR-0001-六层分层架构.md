# ADR-0001 · 采用六层分层架构

## 背景
项目需要支持点对点消息、分布式计算、内容分发、游戏大厅、话语权回归等多能力，架构需保证各模块独立可演进。

## 选项
1. **六层分层**（通信/会话身份/数据/计算/信任策略/应用）
2. 微服务式（按能力拆分服务，服务间 API 通信）
3. 无分层平铺模块

## 决策
**采用六层分层架构**。

## 理由
- 下层（传输/会话）稳定，上层（应用/大厅）可插拔，解耦清晰。
- 各层独立演进、独立验收，符合「AI 可读 + 人类可俯瞰」总则。
- 跨层依赖通过显式接口契约管理，便于风险追踪。

## 否决项
- 微服务式在 P2P 场景下不可行（无中心服务），否决。
- 无分层平铺模块在能力增多后难以维护，否决。

## 影响
- 新增能力按层定位落位。
- 跨层调用必须走接口契约，不得越层。
