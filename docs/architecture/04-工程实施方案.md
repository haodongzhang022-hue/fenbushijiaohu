## 3. 接口契约（v1 草案）

### 3.1 身份
```ts
interface Identity {
  publicKey: string;       // Ed25519 公钥
  sign(msg: string): string;
  verify(pubKey: string, msg: string, sig: string): boolean;
}
```

### 3.2 消息条（会话核心）
```ts
interface Message {
  id: string;              // UUID / 内容哈希
  sender: string;          // 发送者 pubKey
  channelId: string;       // 频道
  type: 'text' | 'media' | 'game-cmd' | 'task';
  payload: string;
  ts: number;              // Lamport/逻辑时钟（CRDT 收敛用）
}
```

### 3.3 传输适配器
```ts
interface Transport {
  connect(peer: PeerDesc): Promise<Channel>;
  listen(cb: (msg: Message) => void): void;
  close(): void;
}
// PeerDesc 由信令交换（含 ICE/SDP，走 WebRTC）
```

### 3.4 联网策略
```ts
interface Policy {
  mode: 'online' | 'lan' | 'offline';
  canBroadcast(): boolean;
  canReceive(): boolean;
  shouldUseRelay(): boolean; // NAT 穿透失败时
}
```

### 3.5 计算任务（P2 预留）
```ts
interface Task {
  id: string;
  type: string;            // 注册的计算类型
  input: string;
  replicas: number;        // 副本数（校验用）
}
```

## 4. 里程碑交付物（MVP 关闭标准）
- 两个网页端通过信令建立 WebRTC 直连。
- 消息条实时收发，多端离线后 CRDT 收敛一致。
- 用户可切换 在线/局域网/离线 策略。
- 局域网内两节点可直接通讯（不依赖外网）。

---

## 5. 技术选型建议
| 用途 | 建议 | 理由 |
|------|------|------|
| P2P 传输 | WebRTC（浏览器）/ libp2p（Node） | 成熟、跨平台 |
| 一致性 | Yjs（CRDT） | 成熟、多端收敛 |
| 身份 | Ed25519（TweetNaCl） | 轻量、签名验证 |
| 信令 | 轻量 WebSocket 服务 | 仅用于交换 SDP/ICE |
| 数据格式 | protobuf + 内容哈希 | 紧凑、可寻址 |

## 6. 跨层契约矩阵（G6 补齐）

> 对齐 10 号审查缺口 G6：「缺跨层契约矩阵 + 版本协商」。本节标注每条接口的上游/下游/破坏影响。

### 6.1 接口契约矩阵

| 接口 | 所属层 | 上游调用方 | 下游实现 | 破坏影响 | 版本 |
|------|--------|-----------|---------|---------|------|

| `Identity.sign(msg)` | 会话身份层 | session / reputation | Keystore / Identity | 中 | v1 |
| `Identity.verify(pubKey, msg, sig)` | 会话身份层 | session / transport | Keystore / Identity | 中 | v1 |
| `Session.send(msg)` | 会话身份层 | app / lobby | session | 高 | v1 |
| `Policy.mode` | 信任策略层 | session / transport | policy | 中 | v1 |

### 6.2 版本协商规则

1. **向上兼容**：所有接口默认只加不改，新增字段可选。
2. **破坏性变更**：修改已有接口签名时，需在 `Fed.protocolVersion` / `Transport` 版本号递增，并在本矩阵记录变更。
3. **变更流程**：变更方提出 → dongjiagoushi 评审 → 更新矩阵 → 更新 ADR → 进入开发。
4. **测试保障**：接口变更须同步更新对应包测试断言，确保 CI 信号灯全绿。
